# First Person Legs

Renders a viewmodel of your lower half.  If you've ever looked down at your legs in a game and been like "where the heck are my shins at", this mod fixes that.  For all three of us.

Personally speaking, I played Destiny and Destiny 2 for far, far too long, and nowadays I always find myself missing the lower half viewmodel in my games... so here it is in Vintage Story.

## Features

- Draws your character's lower body (feet, shins, thighs, pelvis) while in first-person view, reusing the same shader and animation state as the vanilla first-person hands so it stays in sync with your movement, sneaking, and swimming animations.
- Approximates Immersive First Person's torso fold when you look straight down, so the legs lean and shift out of the way instead of completely blocking your view.
- If the default doesn't match your camera preferences, or the legs are too large, you can alter the FOV the legs render at in `firstpersonlegs.json`.
- Optional: if [ConfigLib](https://mods.vintagestory.at/configlib) is installed, every mod setting can be tweaked in-game through its UI.  If it isn't, the mod works fine on its own!
- Client-side only, so there's no server component, and it should be generally safe to use on servers that don't have it in their mod list.

## Configuration

On first load, the mod writes `ModConfig/firstpersonlegs.json` with a default render FOV of 70 degrees.  You can edit it by hand, or use ConfigLib's in-game settings menu if you have it installed.

### <ins>Available settings</ins>

| Setting | Description | Default |
| --- | --- | --- |
| `FpLegsEnabled` | Render the player's own legs in first person. | `true` |
| `LegRenderFov` | Fixed FOV (degrees) the legs render through, independent of world FOV. | `70.0` |
| `VerboseLogging` | Log diagnostics on every leg-mesh rebuild.  Useful for debugging compatibility with player-model mods. | `false` |

3. Package a release zip with `./build.sh` (or `build.ps1` on Windows, or `dotnet run --project CakeBuild/CakeBuild.csproj` directly).  This runs the full Cake pipeline and drops a zip in `Releases/`, named from `modinfo.json`.
4. To debug in-game, use the "Launch Client" VS Code launch config.  It builds Debug, then starts the game pointed at the freshly built mod.

There are no automated tests in this repo, so make sure to test your changes in the launched client.

## Contributing

Issues and pull requests are welcome!  A few things that'll make review go smoother:

- Keep change scope small.  This is a small mod, but a PR that fixes one thing is still much easier to figure out than one that fixes three.
- If you're changing anything around the first-person rendering math, please actually test it in-game (looking straight down, swimming, sneaking, and at a couple of different FOV settings) before opening the PR.  This stuff is easy to get subtly wrong.
  - Using a temporary ConfigLib config entry is a great way to tweak values on the fly to find a good baseline.
- New/changed config settings need a matching lang key in `assets/firstpersonlegs/lang/en.json` (see `FirstPersonLegsConfig.cs` for the pattern) or ConfigLib will show the raw key instead of a label.
- Make sure to add a short summary of your changes to [changelog.txt](FirstPersonLegs/changelog.txt) under the latest unreleased version.
  - You can bump the version in [modinfo.json](FirstPersonLegs/modinfo.json) if you need to.
- If you use an AI assistant to generate code, a quick note to that effect in the pull request is appreciated in the same spirit as the disclosure above.
  - Do not submit AI-generated assets.  This includes models, textures, sounds... basically anything that isn't code.
  - All AI generated code *must* be verified in-game by yourself or another human.  *Never* assume that just because the assistant is fast that it knows what it is doing.  I also request that you look over all AI generated code to make sure it conforms to the architecture of the mod.
